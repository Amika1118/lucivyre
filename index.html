The Player

A full music player, built from scratch.

Lucivyre isn't a wrapper around Spotify or VLC. It reads your files, builds its own library, tracks what you play, and learns from every skip and replay - all in pure Python.

🎵

Metadata & playback

Reads title, artist, duration, and artwork via mutagen. Streams audio with pygame.mixer across MP3, WAV, FLAC, and OGG.

Library scan

Point it at a folder, and it walks the tree, filters audio files by MIME type, and builds a searchable index. Handles 1,000+ song catalogs.

Search

Search by title, artist, or both. Case-insensitive contains matching across the whole library. Queue a song from search and it plays next - mid-playback.

The Shuffle

Not random. Not rigid.
Just fair.

Regular shuffle treats every song the same - it doesn't care what you love. Lucivyre gives each song a score. That score is mapped to an effective score across three tiers, then shaped into a random key so high-scoring songs drift toward the top without ever being locked there.

GO
score > 15.0
S' = S × 3.0
Heavy boost. Songs you keep coming back to get pushed toward the top of every shuffle - but never rigidly.
MID
5.0 ≤ score ≤ 15.0
S' = S
Standard weight. The baseline of 10.0 lives here - the neutral listening zone where most songs sit.
NO
score < 5.0
S' = max(S, 0.05) × 0.1
Heavy penalty. Skipped songs sink to the bottom, but never quite disappear - they still have a small chance to resurface.
NO · penalized
MID · neutral
GO · boosted
0.0 5.0 15.0 25.0+

Exponential key sampling (A-ES)

For each song, draw a uniform random number and compute a key. Sort by key descending. Higher effective scores cluster near the top, but every shuffle is different - low-scoring songs still surface sometimes. 

import math, random

def effective_score(score):
    if score > 15.0:
        return score * 3.0          # GO tier
    if score < 5.0:
        return max(score, 0.05) * 0.1  # NO tier
    return score                    # MID tier

def shuffle(songs):
    keys = []
    for song in songs:
        u = random.uniform(0.0001, 0.9999)
        s_prime = effective_score(song["score"])
        k = math.log(u) / s_prime
        keys.append((k, song))
    keys.sort(key=lambda x: x[0], reverse=True)
    return [s for _, s in keys]

Time complexity is O(N log N) for a full pass, or O(N log K) with a heap when you only need the top K. Memory is O(N).

What's next.

The player runs today. From here: move scoring into SQLite, wire the shuffle into the player, and let feedback flow back automatically on every listen.

Core player Done

Playback, metadata, library scan, search, playlists, live controls, dual timers.

Credit system Done

Skips deduct credits proportionally. Full plays keep them. Search plays earn bonus points.

Shuffle algorithm design Done

Three-tier effective score mapping and exponential key sampling fully specified.

SQLite score store In progress

scores.db with an item_scores table. Atomic upserts via ON CONFLICT DO UPDATE. CSV import/export for portability.

Shuffle integration Next

Plug the effective-score + key sampling shuffle into the player's shuffle mode.

Automatic feedback loop Next

Skips, full plays, and searches update scores by ±0.05 / ±0.1 in real time. Scores persist across sessions.

Vectorized performance Later

NumPy-based key sampling for 1,000+ item catalogs. Heap-based top-K extraction for large queues.

Recommendations Later

Use score history to surface songs you haven't heard in a while - discovery without randomness.
